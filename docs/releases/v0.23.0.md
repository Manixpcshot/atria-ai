# آتریا v0.23.0 — کدکس: لایهٔ اعتماد کدنویسی

حالت کدکس از «پیوست prompt» به یک **لایهٔ اعتماد اجرایی** ارتقا یافت — مستقل از Full Access، با انتخاب صریح کاربر (کلید ⌨).

## معماری اعتماد (سه لایه)

| لایه | فعال‌سازی | ترمینال | فایل‌نویسی | وب/GitHub/MCP |
|---|---|---|---|---|
| عادی (ask) | پیش‌فرض | staged (تأیید در چت) | staged (diff + تأیید) | staged |
| **کدکس** | کلید ⌨ | **مستقیم** — CWD = پروژه/workspace، log کامل، بدون escalation | **خودکار + backup** — محدودهٔ پوشهٔ خانگی کاربر | staged (بدون تغییر) |
| Full Access | opt-in صریح | مستقیم — CWD = پروژه/workspace | خودکار + backup — workspace/profile/system (تنظیم‌شده) | دانلود/URL خودکار؛ GitHub allowlist خودکار |

## تغییرات هسته (atria-core)

- `ClientConfig.codex_mode: bool` — جدید.
- `agent.rs`:
  - کاتالوگ فایل در کدکس = توصیف اعتماد FA-profile (auto-write + backup، بدون system scope).
  - کاتالوگ ترمینال در کدکس = توصیف «اجرای مستقیم log‌شده».
  - dispatch: `write_file` در کدکس → `auto_file_write_full_access(profile=true, system=false)` (با backup و guardهای مسیرهای حساس).
  - `execute_async_tool` پارامتر `terminal_direct` گرفت: فقط `run_command`/`run_code` مستقیم می‌شوند؛ گیت‌های `open_url`/`download_*`/GitHub **تغییر نمی‌کنند**.
- `tools.rs`: متن‌ها دقیق‌تر/چندسازهمانند؛ ۴ تست واحد تازه.
- `tests/codex_profile_write.rs` (یکپارچه): profile-scope auto-write + backup + `restore_file_backup` + مسدودشدن `.ssh` و مسیّرهای مطلق.

## اپلیکیشن (atria-app / CLI)

- `commands.rs` حالا `codex_mode` را به هسته فوروارد می‌کند (قبلاً dead-code بود).
- CLI: `codex_mode: false` ثابت — CLI لایهٔ اعتماد خودش (`--full`) را دارد.

## فرانت‌اند

- چیپ «⌨ کدکس» (سبز) در `composer-status` کنار چیپ پروژه؛ با `syncCodex()` همگام.
- ورود به کدکس بدون پروژه → toast پیشنهاد انتخاب پوشهٔ پروژه.
- `CODEX_MODE_BLOCK` بازنویسی شد: شرح دسترسی‌های فعال (ترمیمال مستقیم log‌شده، نوشتن خودکار با backup)، روش کار (بخوان/ویرایش/تست/git-بهداشت/گزارش نهایی). نام ابزار هم اصلاح شد (`write_file` به‌جای `edit_file`).
