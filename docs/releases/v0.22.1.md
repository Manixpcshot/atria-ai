# آتریا v0.22.1

پچ لایهٔ لینوکس — باگ آیکن تسکبار (مخصوصاً AppImage) + دو باگ واقعی که در باگ‌گیری پیدا شد.

## 🐞 آیکن تسکبار لینوکس (مخصوصاً AppImage)

**علائم:** آیکن تسکبار «یک‌هو می‌آمد و یک‌هو می‌رفت» — پنل گاهی آیکن نشان نمی‌داد یا با تأخیر/دوباره‌سازی عوض می‌شد.

**ریشه:**
1. پنجره هیچ `_NET_WM_ICON` قابل‌اعتمادی نداشت → پنل به «کَش تم آیکون» دسکتاپ اعتماد می‌کرد. در AppImage، ریشهٔ فایل‌ها روی mount با نام تصادفی است و کَش تم برای آن بی‌ثبات است → فلش.
2. فایل `.desktop` تولیدی ناقص بود: بدون `StartupWMClass` (پنل نمی‌توانست پنجره را به برنامهٔ Atria وصل کند)، بدون `Categories`/`Keywords` و با توضیح اشتباه «built for Windows».

**ترمیم (هر دو بستهٔ .deb و .AppImage):**
- **آیکن پیکسلی ۵۱۲px در لحظهٔ ساخت پنجره روی خود پنجره تنظیم می‌شود** (`WebviewWindowBuilder::icon`) → GDK همان لحظهٔ map خاصیت `_NET_WM_ICON` را می‌نویسد. نتیجهٔ تست (Xvfb + openbox): آیکن از **فریمِ نخست** موجود و ثابت است — دیگر هیچ وابستگی به کَش تم نیست.
- **`.desktop` واقعی** (`crates/atria-app/desktop/Atria.desktop.in` از طریق `bundle.linux.deb.desktopTemplate`): `Name=Atria`، `StartupWMClass=Atria` (مطابق WM_CLASS واقعی)، `Categories=Utility;Network;`، `Keywords`، `Comment` درست. AppImage هم همین قالب را می‌جست.
- **آیکون‌های hicolor** (۳۲ تا ۵۱۲) داخل هر دو بسته؛ **postinst/postrm** در .deb بعد از نصب/حذف `update-desktop-database` و `gtk-update-icon-cache` می‌دوند.
- `Section=utils` و توضیح خنثی (بدون «for Windows»).

## 🔑 ذخیرهٔ امن کلیدها در لینوکس/macOS (قبلاً کاملاً شکسته بود)

قبلاً `secrets.rs` فقط Windows Credential Manager را می‌شناخت — در لینوکس/macOS **هر** ذخیرهٔ کلید API یا توکن GitHub خطا می‌داد (کاربر لینوکس اصلاً نمی‌توانست اتصال را ذخیره کند). حالا:
- پلتفرم‌های غیرویندوز: فایل `~/.atria/secrets/{id}.key` — پوشه `0700`، فایل `0600`، ایجاد با `O_EXCL` (هیچ مسیر از پیش موجودی دنبال/جایگزین نمی‌شود). همان الگوی `~/.netrc`/`~/.git-credentials`.
- ویندوز: بدون تغییر (Credential Manager) + **یک‌بارمِجرات** خودکار از فایل DPAPI قدیمی.
- متن‌های فرانت‌اند خنثی شد (دیگر «Windows Credential Manager» در لینوکس دیده نمی‌شود).
- تست تازهٔ round-trip (atria-app: 4/4).

## 🐛 باگ مهم: `atria-cli --update` در لینوکس

در لینوکس، آپدیت خودکار اشتباهاً اَست **ویندوزی** (`atria-cli.exe`) را انتخاب و روی باینری لینوکس جایگزین می‌کرد — یعنی آپدیت، CLI را **خراب می‌کرد**. حالا:
- انتخاب اَست **بر اساس پلتفرم** (`cli_asset_name`): ویندوز `atria-cli.exe`، مک `atria-cli`، لینوکس `atria-cli-linux-x86_64`؛ پلتفرم بدون اَست → پیام واضح + راهنمای دانلود دستی.
- بعد از جایگزینی، بایت اجرا (`0755`) دوباره تنظیم می‌شود.
