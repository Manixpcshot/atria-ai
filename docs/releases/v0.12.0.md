# آتریا v0.12.0

## اصلاح‌های امنیتی

- **محدودهٔ فایل‌ها به ورک‌اسپیس:** `list_files` و `read_file` دیگر مسیر مطلق، `..`، symlink یا مسیرهای حساس مرورگر/اعتبارنامه را نمی‌پذیرند. فهرست‌کردن ورودی‌های حساس را نشان نمی‌دهد. خواندن و diff فقط داخل پوشهٔ کاری مجاز هستند.
- **حفاظت از کلیدها در فایل‌های معمولی:** اگر محتوای خوانده‌شده یا diff پیش‌نمایش شامل الگوهای متداول کلید، پسورد یا توکن باشد، محتوا به مدل بازگردانده نمی‌شود و ویرایش مسدود می‌گردد.
- **اعمال و Undo امن‌تر:** مسیر staging، apply و undo دوباره اعتبارسنجی می‌شود. backup فقط از اسلات خودش و با سقف اندازه و UTF-8 معتبر بازگردانی می‌شود. Undo برای فایل تازه‌سازِ قبلاً حذف‌شده نیز idempotent است.
- **برش UTF-8 هنگام خواندن:** خواندن فایل با سقف ۲۵۶ کیلوبایت، دیگر یک نویسهٔ چندبایتی را نصف نمی‌کند.
- **جلوگیری از SSRF در وب:** همهٔ آدرس‌های DNS قبل از اتصال بررسی می‌شوند. محدوده‌های CGNAT، reserved، documentation و IPv6 غیرعمومی مسدود هستند. پروکسی محیطی نمی‌تواند DNS بررسی‌شده را دور بزند. redirectها به‌صورت دستی، با اعتبارسنجی و pinning دوباره دنبال می‌شوند.
- **SSE پایدارتر:** اگر یک رویداد خالی بعد از `event:` بیاید، نام رویداد قبلی به رویداد بعدیِ پیش‌فرض نشت نمی‌کند.

## محدوده و ایمنی

Full Access دسترسی نامحدود سیستم‌عامل نیست و هنوز فقط پس از انتخاب صریح کاربر فعال می‌شود. این نسخه کنترل حساب‌های Windows یا مرورگر را اضافه نمی‌کند. خواندن و فهرست‌کردن فایل همیشه به ورک‌اسپیس محدود است. Full Access فقط محدودهٔ نوشتن خودکار فایل را بین workspace و پروفایل کاربر، با حذف مسیرهای حساس، کنترل می‌کند. توکن GitHub در Windows Credential Manager می‌ماند و به مدل یا گفتگو ارسال نمی‌شود.

عملیات GitHub در حالت پیش‌فرض کارت تأیید جداگانه می‌خواهند؛ فقط Full Access صریح، عملیات allowlist‌شده را بدون prompt موردی اجرا می‌کند. دستیار هنوز نمی‌تواند تنظیمات Atria را تغییر دهد یا اتصال‌های ارائه‌دهنده را انتخاب یا ویرایش کند؛ این کارها از صفحهٔ Settings انجام می‌شوند. ابزار shell، دسترسی مدیر، حذف مستقیم، merge، secrets و تنظیمات GitHub فعال نشده‌اند.
