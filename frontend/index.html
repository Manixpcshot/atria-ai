اتصال‌ها و مدل‌ها

ارائه‌دهنده‌ها، آدرس API، کلیدها و مدل‌های قابل انتخاب را مدیریت کن.

کلیدها در Windows Credential Manager و برای حساب فعلی ذخیره می‌شوند؛ در localStorage فقط مشخصات اتصال می‌ماند.
برچسب‌های تصویر/ابزار/استدلال را روی هر مدل روشن یا خاموش کن؛ مقدار اولیه از نام مدل حدس زده می‌شود.
فقط مدل‌هایی که همین‌جا اضافه کنی در منوی چت نمایش داده می‌شوند. با «دریافت از سرور» فهرست مدل‌های واقعی سرور می‌آید؛ روی هرکدام کلیک کن تا اضافه یا برداشته شود.
هر سرویس‌دهنده می‌تواند چند اتصال جدا با کلید و مدل‌های خودش داشته باشد. مدل‌های منوی چت دقیقاً همان‌هایی‌اند که برای هر اتصال تعیین کنی — فهرست پیش‌فرضی در کار نیست.

ابزارهای GitHub
خواندن مخزن/issue/PR و آماده‌سازی تغییر؛ هر نوشتن GitHub همیشه نیازمند تأیید جداگانه است.
حالت خودکارِ محدود فقط پیوند عمومی را باز می‌کند و فایل داخل ورک‌اسپیس را با پشتیبان تغییر می‌دهد. برای حذف تأییدهای تک‌به‌تکِ GitHub و گسترش نوشتن فایل، گزینهٔ دسترسی خودکار گستردهٔ پایین را جداگانه روشن کن.
Full Access — دسترسی خودکار گسترده
برای ابزارهای فعالِ فایل، وب و عملیات پشتیبانی‌شدهٔ GitHub تأیید جداگانه نمی‌گیرد؛ از درخواست بعدی اعمال می‌شود و نتیجهٔ هر ابزار ثبت می‌شود. خاموش‌کردن حین اجرا، توقف پاسخ جاری را درخواست می‌کند؛ اقدامی که شروع شده ممکن است کامل شود.
پروفایل یعنی مسیرهای نسبی داخل پوشهٔ کاربر؛ AppData، داده‌های خصوصی آتریا، پوشه‌های حساس کلید/اعتبارنامه/پیکربندی (مثل .ssh و .config)، فایل‌های .env و مسیرهای symlink مسدودند. نوشتن پشتیبان قابل‌بازگردانی می‌سازد. مجوز توکن GitHub گسترش نمی‌یابد؛ شِل، دسترسی مدیر، حذف مستقیم، merge، secrets یا تنظیمات GitHub فعال نمی‌شوند (نوشتن محلی و به‌روزرسانی GitHub می‌توانند محتوای فایل را جایگزین کنند). محتوای فایل‌های خوانده‌شده ممکن است برای تحلیل به مدل فعال فرستاده شود.
GitHub — دسترسی امن
وضعیت اتصال در حال بررسی…
توکن فقط در Windows Credential Manager ذخیره می‌شود و به مدل/گفتگو فرستاده نمی‌شود. محتوای خصوصی‌ای که ابزار GitHub می‌خواند، برای تحلیل به مدل فعال فرستاده می‌شود. حداقل دسترسی پیشنهادی: Metadata خواندنی؛ برای نوشتن، فقط Contents (read/write)، Issues (read/write) و Pull requests (read/write) در مخزن‌های لازم. هیچ توکنی را در این گفتگو نفرست.
اگر پاسخ به سقف برسد، برنامه تا ۳ بار ادامه‌اش می‌دهد. سقف هر بخش حداکثر ۶۵۵۳۶ توکن است و ربطی به اعتبار حساب ندارد.

گفتگوها

یوزر توکن دیپ‌سیک از کجا بیاورم؟

  1. در مرورگر وارد chat.deepseek.com شو و وارد حساب خودت شو
  2. F12 بزن (Developer Tools) و به تب Application برو
  3. در سمت چپ: Local Storage ← آدرس سایت ← آیتم userToken
  4. یا در تب Console این دستور را بزن:
JSON.parse(localStorage.getItem("userToken")).value
  1. رشتهٔ برگشته را کپی کن و در فیلد «یوزر توکن» همین‌جا بگذار
  2. می‌توانی کل مقدار userToken را هم بگذاری — برنامه خودش بخش value را می‌خواند

⚠ غیررسمی و با مسئولیت خودت — ممکن است سایت دیپ‌سیک محدود کند؛ توکن حدود یک روز معتبر است و بعد باید دوباره بگیری.
